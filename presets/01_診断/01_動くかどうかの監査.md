## 説明

このマクロが対象の環境で動くかどうかを、事実として確かめます。

## 返す形

指摘型

## 返す節

- PURPOSE
- FLOW
- DEPENDENCY
- ENVIRONMENT

## 改修指示

添付した VBA コードの全体を読み、このマクロの目的、処理の流れ、依存関係、
そして **対象の環境で動くかどうか** を監査してください。

コードのほかに資料（仕様書、手順書、エラーの画面、対象データの例など）が
添付されている場合は、それも読んだうえで診断してください。
コードと食い違う点があれば、どちらが何を示しているかを事実として書いてください。
添付が無い場合に、追加の資料を求める必要はありません。

コードは書き換えません。改修方針、直し方、修正後の動作予測、修正コードは書かず、
確認できる事実、その成立条件、影響、根拠だけを報告してください。
曖昧なことは断定せず、確認できない理由を明示してください。

### 何を「動かない」とするか

次のどれかに当たるものを挙げてください。**想定動作環境が原因かどうかは問いません。**

- 実行前のコンパイルで止まる（宣言の不整合、存在しない参照、構文）
- 実行時に必ず、または特定の条件で落ちる
- 落ちはしないが、明らかに不合理な動作をする
  （必ず偽になる分岐、初期化していない変数の使用、届かないコード、
  取り違えたシート名や列位置など）
- 想定動作環境の制約に当たって成立しない

**遅い・読みにくい・整っていないは挙げないでください。** 動いているものは
この監査の対象外です。

### どこを探すか

改修ガイド §4 Step 2 の検索対象です。ここに無い形でも、動かないなら挙げてください。

- パス: `\\`、`:\`、`.Path`、`.FullName`
- ファイル操作: `Dir`、`Open`、`Kill`、`FileCopy`、`FileSystemObject`
- API: `Declare`、`Lib`、`PtrSafe`
- Shell: `Shell`、`WScript.Shell`、`Shell.Application`
- DB 接続: `ConnectionString`、`Provider=`、`OLEDB`、`ODBC`
- 外部実行: `.Run`、`.Exec`

### 保存先が変わったときに崩れる前提

改修ガイド §3.1 の留意点です。これらを置いている処理は、保存先の変更で
成立しなくなることがあります。

- カレントディレクトリが存在する
- 相対パスで常に同じファイルを参照できる
- URL を `Open`、`Dir`、`FileSystemObject` 等へ直接渡せる
- ファイルサイズ、更新日時、属性をローカルファイルと同様に取得できる
- ファイルを排他制御なしで上書きできる

### 各指摘について確かめること

改修ガイド §4 Step 3 です。EVIDENCE と IMPACT に反映してください。

- どの入力を受けるか
- どのファイル、DB、外部機能に依存するか
- どのプロシージャから呼ばれるか
- 失敗時にどの状態が残るか

### 判定（GRADE）

指摘ごとに A〜D を1つ付けます。

- **A** … 動作に支障なし
- **B** … 動かない。**VBA のソースを書き換えれば直る**
- **C** … 動かない。原因が VBA のソースの外にある（参照設定、Power Query の
  接続、ActiveX コントロール、フォント、署名、信頼設定）。ソースの書き換えでは
  直らないが、環境側で手を打てる余地はある
- **D** … 動かない。**置き換え先が存在しない**。VBA 標準にも、この端末で使える
  代替にも、同じことをする手段が無い

`GRADE=D` は最も重い結論です。次を満たさないものは D ではなく C にしてください。

- 何がどの標準機能で置き換えられないのかを EVIDENCE に書く
- `CONFIDENCE=CONFIRMED` である。「たぶん無理」は D ではありません

### 指摘のまとめ方

**場所ごとではなく原因ごとにまとめてください。**
同じ原因が 10 か所にあるなら、それは 10 件ではなく 1 件です。
場所は MODULE / PROC / LINES で示し、代表的な箇所を EVIDENCE に書きます。
同じことを言い換えた指摘を並べたり、1 か所ずつ機械的に列挙したりしないでください。

4 つの SECTION は指摘が 0 件でも省略しないでください。指摘には必ず、該当する
モジュール・プロシージャ・可視コードの行番号を規則どおり付けます。
該当箇所を名乗れない項目は `-` とし、存在しない名前や行番号を作らないでください。

## 出力指示

### 1. 返す形（この 5 つだけが必須です）

1. 回答はチャットの本文に書き、診断の結果は**ひとつだけのコードブロック**へ
   まとめる。開始フェンスはバッククォート 3 個だけにし、`text` や `vb` などの
   言語名を付けない。
   コードブロックの外には、あいさつ、前置き、要約、感想を書かないでください。
2. `'@MACROSTUDIO {{REQUEST_ID}}` で始まる区切りの行は 1 行に 1 つだけ、
   書かれたとおりの語で書く。依頼番号は差し替えない。
3. **SECTION** を PURPOSE / FLOW / DEPENDENCY / ENVIRONMENT の 4 種、1 回ずつ、
   1 行ずつ。
4. **FINDING** は 1 件につき、区切り 1 行（番号と META）＋
   `TITLE:` `CONDITION:` `IMPACT:` `EVIDENCE:` の 4 行。
   META には `GRADE` `CONFIDENCE` `MODULE` `PROC` `LINES` `ENVKEY` の 6 つを
   **それぞれ 1 回ずつ**書く。**並べる順番は問いません。**
   値が無い項目は `-` と書き、6 つを省略しない。
5. `DIAG BEGIN <件数>` と `DIAG COMPLETE <件数>` の数字は、**どちらも
   この返答に書いた FINDING の件数**。4 件書いたなら `DIAG BEGIN 4` と
   `DIAG COMPLETE 4`。版番号ではありません。

指摘が 0 件のときは FINDING を書かず、`DIAG BEGIN 0` で始め、
`DIAG NOFINDING SCOPE_CLEAR` か `DIAG NOFINDING INSUFFICIENT` を 1 行だけ書き、
`DIAG COMPLETE 0` で終えます。指摘があるときに NOFINDING は書きません。

### 2. そのまま真似できる記入例

```
'@MACROSTUDIO {{REQUEST_ID}} DIAG BEGIN 2
'@MACROSTUDIO {{REQUEST_ID}} SECTION PURPOSE 支店ごとの売上データを読み込み、月次の集計表を作って所定のフォルダへ保存するマクロです。
'@MACROSTUDIO {{REQUEST_ID}} SECTION FLOW MonthlyReport.Main が入口です。CommonUtil で共有フォルダのブックを開き、SalesRules で支店ごとの集計を行い、ReportFormatting で書式を整えたあと、CoverSheet で表紙を作って保存します。
'@MACROSTUDIO {{REQUEST_ID}} SECTION DEPENDENCY 共有フォルダ上の「支店データ.xlsx」を開きます。待ち時間の処理に Windows の Sleep 関数を使っています。外部の参照ライブラリは使っていません。
'@MACROSTUDIO {{REQUEST_ID}} SECTION ENVIRONMENT 提示された環境では、Windows の関数を直接呼ぶ処理と、固定のドライブ文字を前提にしたファイルの読み書きが、そのままでは動きません。集計そのものの処理は環境に依存していません。
'@MACROSTUDIO {{REQUEST_ID}} FINDING 1 GRADE=B CONFIDENCE=CONFIRMED MODULE=CommonUtil PROC=WaitSeconds LINES=8,21 ENVKEY=WIN32API_BLOCKED
TITLE: 待ち時間の処理が Windows の関数を直接呼んでいるため、実行できません。
CONDITION: このマクロを実行すると必ず通ります。分岐や設定で避けられる箇所ではありません。
IMPACT: マクロが最初の待ち時間で止まり、それ以降の集計も保存も行われません。書きかけのファイルは残りません。
EVIDENCE: CommonUtil の 8 行目に Declare による Sleep の宣言があり、21 行目の WaitSeconds がそれを呼んでいます。WaitSeconds は MonthlyReport.Main から 3 か所で呼ばれています。待ち時間は Application.Wait で置き換えられます。
'@MACROSTUDIO {{REQUEST_ID}} FINDING 2 GRADE=B CONFIDENCE=CONFIRMED MODULE=SalesRules PROC=Aggregate LINES=64 ENVKEY=-
TITLE: 集計対象のシート名が実在しないため、実行すると必ず止まります。
CONDITION: Aggregate を通ると必ず起きます。環境には関係ありません。
IMPACT: 集計の手前で実行時エラーになり、表紙も保存も行われません。
EVIDENCE: SalesRules の 64 行目が Worksheets("売上一覧") を参照していますが、このブックにあるのは「売上明細」です。ほかの 3 か所は「売上明細」を使っています。
'@MACROSTUDIO {{REQUEST_ID}} DIAG COMPLETE 2
'@MACROSTUDIO {{REQUEST_ID}} DIAG END
```

### 3. 値の決め方

- `GRADE=D` には `CONFIDENCE=CONFIRMED` と、置き換えられない理由が必要です。
- `CONFIDENCE` は、実機での発生を確認していない指摘では原則 `LIKELY` とします。
- `ENVKEY` は、想定動作環境の制約に当たる指摘だけが名乗ります。環境と関係のない
  故障は `-` にしてください。存在しないキーを作らないでください。
- `LINES` は、添付テキスト全体の通し行番号ではなく、MacroStudio が表示する
  各モジュールの可視コード行番号です。カンマ列でも範囲でもよく、該当モジュール内に
  実在する行だけを指します。
- `TITLE` は改行せず 120 文字以内。`EVIDENCE` にはコード上の根拠を書きます。
- どの `TEXT` にも「どう直すか」は書きません。マクロを書かない人にも読める言葉で
  書きます。

### 4. チャットの整形で失敗しないために

これはチャット画面の飾りを避けるための注意で、上の契約とは別のものです。

- コードブロックは回答全体で 1 個だけにし、途中で分けないでください。
- コードブロックの中に空行を入れないでください。先頭と末尾にも入れないでください。
- SECTION の本文と、TITLE / CONDITION / IMPACT / EVIDENCE の本文は、
  それぞれ改行せず 1 物理行で書いてください。
- 引用記号 `>`、箇条書き記号、HTML の `<code>` や `<pre>` を使わないでください。
- 行頭のアポストロフィは半角 `'` です。全角や曲がった引用符に変えないでください。
- ダウンロード用のテキストファイル、添付ファイル、ダウンロードリンクでは
  返さないでください。
- コードは書き換えず、修正コードや改修案は返さないでください。
