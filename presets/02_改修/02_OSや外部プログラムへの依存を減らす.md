## 説明

OSの機能や外部プログラムに頼っている処理を、Excel標準の書き方へ置き換えてもらいます。

## 分類

環境依存・外部実行の見直し

## 認める構造変更

- モジュール追加

## 推奨条件

- SHELL_EXEC_BLOCKED
- SCRIPT_HOST_BLOCKED
- WMI_BLOCKED
- DLL_LOAD_BLOCKED
- DDE_IE_UNAVAILABLE
- LEGACY_UI_AUTOMATION
- DAO_UNAVAILABLE
- POINTER_AND_32BIT

## 希望動作の候補

- 今までと同じ結果になるように直してほしい
- 置き換えられない箇所は、無理に直さず理由を返してほしい
- 外部に頼る処理そのものが不要なら、なくしてほしい

## 維持すること

- 明示していない業務動作は変えない
- 公開しているプロシージャ名・引数は変えない
- 判断できないことは勝手に決めず、決める必要があることとして返す

## 改修指示

外部プログラムの起動やOSの機能に頼っている箇所を、対象環境でも動く形へ
改修してください。

コードのほかに資料（仕様書、手順書、エラーの画面、対象データの例など）が
添付されている場合は、それも読んだうえで改修してください。
添付が無い場合に、追加の資料を求める必要はありません。

対象は次の依存です。特定の関数名だけに限定せず、コード全体から探してください。

- 外部プログラムやコマンドの起動（Shell、WshShell の Run / Exec など）
- スクリプトホストやシェルの自動化オブジェクトの生成
- WMI 経由での端末情報の取得や操作
- 実行時に読み込む DLL、COM への依存
- DDE や、ブラウザ・他アプリの画面を外から操作する処理
- 32 ビットを前提にした型・ポインタ・API 宣言の扱い
- 対象環境に無いかもしれない参照ライブラリへの依存

優先順位は次のとおりです。上から順に検討し、下へ落とす理由を SUMMARY に書いてください。

1. その依存が業務上ほんとうに必要かを見る。不要なら処理ごとなくす。
2. Excel / VBA の標準機能へ置き換える。
   ファイル操作なら FileSystemObject ではなく VBA の Dir / Open、
   待ち時間なら Application.Wait、
   ブックの操作なら Workbooks / Worksheets というように、
   Excel が自分でできることは Excel にさせる。
3. どうしても外部が必要な場合だけ、遅延バインドと 32/64 両対応を精査し、
   失敗したことが利用者に分かる形にする。

置き換えた処理は、既存の処理モジュールへ混ぜず、原則として新しい標準モジュールへ
まとめてください。呼び出し側は、その関数を呼ぶ形へ差し替えるだけにします。

次のことはしないでください。

- 「動くようにする」ためにセキュリティ設定の緩和を前提にした改修。
- 依存を別の外部依存へ置き換えただけの改修。
- 測っていない箇所を、速くなるはずという理由で書き換えること。
- 標準機能では等価にならない箇所を、等価であるかのように置き換えること。
  等価にならないなら、そう書いて UNCLEAR または IMPOSSIBLE で返してください。

要約は、直した箇所を 1 つずつ並べるのではなく、方針ごとにまとめてください。
「外部プログラムの起動を廃止（ExportSummary / StartupTasks）」のように、
何をしたかと、それがどのモジュールに及んだかを 1 行で書きます。
変更の細部は、この後の画面で差分として 1 行ずつ表示されます。

## 出力指示

回答はチャットの本文に書いてください。ダウンロード用のテキストファイル、添付ファイル、
ダウンロードリンクでは返さないでください。

変更したモジュールと新しく作ったモジュールの全文を、**ひとつだけのコードブロック**に
まとめて返してください。モジュールごとにコードブロックを分けないでください。

【出力互換性に関する注意事項】

- 開始フェンスはバッククォート 3 個だけにし、`text`、`vb` などの言語名を
  付けないでください。
- コードブロックは回答全体で 1 個だけにしてください。
- 区切りの行の行頭は半角のアポストロフィ `'` です。
  全角や曲がった引用符に変えないでください。
- 引用記号 `>`、箇条書き記号、HTML の `<code>` や `<pre>` を使わないでください。
- コードブロックの外には、あいさつ、前置き、要約、感想を書かないでください。

コードブロックの中は、次の順に書きます。区切りの行は 1 行に 1 つだけ、
そのままの形で書いてください。

まず、何をどう直したかの要約を、この 2 行ではさんで書きます。

'@MACROSTUDIO {{REQUEST_ID}} SUMMARY BEGIN
（何をどう直したか。モジュール名を挙げて 3〜6 行程度。
　マクロを書かない人にも分かる言葉で）
'@MACROSTUDIO {{REQUEST_ID}} SUMMARY END

続けて、モジュールごとに次の行ではさみます。

'@MACROSTUDIO {{REQUEST_ID}} BEGIN <種類> <モジュール名>
（そのモジュールの全文）
'@MACROSTUDIO {{REQUEST_ID}} END <種類> <モジュール名>

すべてのモジュールを書き終えたら、最後に次の 1 行を置いてください。

'@MACROSTUDIO {{REQUEST_ID}} COMPLETE <モジュールの数>

返せる答えは 2 つだけです。改修したコードを上の形で返すか、
改修できない理由を下の形で返すか、どちらかです。
**利用者へ質問を返したり、選択肢を示して選ばせたりしないでください。**
足りない情報があって決められない場合も、質問はせず UNCLEAR で返します。

直すところが無いと判断したとき、この形では直せないと判断したとき、
または渡された情報だけでは決められないときは、
モジュールを 1 つも書かず、代わりに次の形で返してください。
求められていない変更を作って埋めることはしないでください。

'@MACROSTUDIO {{REQUEST_ID}} SUMMARY BEGIN
（なぜそう判断したか。何を見て、どこがそうなっているか。
　マクロを書かない人にも分かる言葉で 3〜6 行程度）
'@MACROSTUDIO {{REQUEST_ID}} SUMMARY END
'@MACROSTUDIO {{REQUEST_ID}} NOCHANGE <判断>
'@MACROSTUDIO {{REQUEST_ID}} COMPLETE 0

<判断> は次の 3 つのどれかです。

- UNNECESSARY … いまのままで依頼の内容を満たしているので、直す必要がない
- IMPOSSIBLE … 直したほうがよいが、渡されたモジュールを書き換える形ではできない
- UNCLEAR … 依頼の内容が、渡された情報だけでは確定できない

UNCLEAR のときは、何がどう決まらないのかを SUMMARY に書いてください。
利用者へ質問を返したり、選択肢を示して選ばせたりしないでください。
この返答で対話は終わりです。決められない理由が読めれば、
利用者は依頼文を書き直して、もう一度渡します。

SUMMARY / NOCHANGE / COMPLETE の各行はすべて必要です。
理由を書かずに NOCHANGE だけを返したり、
COMPLETE 0 だけを返したりしないでください。何も返さないこと、
返答を途中でやめることも、「変更なし」とは扱われません。

守ってください:

- 明示されていない業務動作は変えないでください。
- 公開しているプロシージャ名・引数は変えないでください。
- コードだけでは判断できないことは勝手に決めず、
  決める必要があることとして返してください。
- <種類> は standard / class / form / document のどれかです。
  既存モジュールの <種類> は、依頼文の【対象モジュール】に書かれた種別を
  次のとおり読み替えて書いてください。
  標準モジュール = standard / クラスモジュール = class /
  フォームモジュール = form / ドキュメントモジュール = document
- 新しく増やすモジュールは、必ず standard（標準モジュール）にしてください。
  クラスモジュール・ユーザーフォームを新しく作らないでください。
  既存のクラスモジュールを直すことはできます。
- {{REQUEST_ID}} は今回の依頼の番号です。書き換えたり省略したりしないでください。
- 変更していないモジュールは入れないでください。
- 変更は最小限にする。それ以外の行は、行の順序・空白・インデント・コメント・
  変数宣言の並び・命名を含め、渡したものと一字一句同じにして返す。
- 変更した既存モジュールと、新しく作ったモジュールは、先頭から末尾まで
  省略せず全文を書く。「'（以下変更なし）」のような省略はしない。
- コードブロックの中には、上の区切り行以外の説明文を入れない。
- モジュール先頭に「Attribute VB_」で始まる行を付けない。
- モジュール名の変更と、モジュールの削除はしない。
- 要約は上の SUMMARY の中だけに書きます。コードブロックの外には書かないでください。

## 出力指示（モジュール単位）

ダウンロードリンクでは返さないでください。

コードが長いので、変更するモジュールを **1 回の返答につき 1 つだけ** 出してください。
すべてのモジュールを 1 回の返答にまとめないでください。

進め方:

1. まず、変更するモジュールが全部でいくつになるかを決めます。この数を <合計> とします。
2. 1 回目の返答では、要約と 1 つ目のモジュール（番号 00）だけを出します。
3. 返答の最後に、コードブロックの外で「次のモジュール 01 を出してよいですか」と
   1 行で確認してください。
4. 「はい」と言われたら、次の返答で番号 01 のモジュールを出します。
   以後 02、03 … と、<合計> に達するまで 1 回に 1 つずつ繰り返します。

1 回目の返答だけ、コードブロックのはじめに要約を書きます。
