## 説明

コードは直さず、新しい端末で困りそうな箇所を洗い出してもらいます。

## 用途

診断

## 改修指示

添付したマクロが、新しい業務端末でそのまま動くかどうかを診断してください。
コードは書き換えず、**どこが問題になるか**と**どう直せばよいか**を報告してください。

新しい端末では、次のことが起きます。この前提で読んでください。

- **Win32 API が使えません。** `Declare` / `Declare PtrSafe` による外部 DLL 呼び出しは
  実行できません。宣言だけでなく、その API を呼んでいる箇所も動かなくなります。
- **外部プログラムの起動が使えません。** `Shell`、`WScript.Shell`、`cmd /c`、
  PowerShell・VBScript・`mshta` などの起動は止められます。`CreateObject` で
  シェルや WMI を呼ぶ箇所も同じです。
- **ブックの置き場所が変わり、パスが URL になります。** ブックが SharePoint /
  OneDrive 上に置かれると `ThisWorkbook.Path` は `https://…` を返します。
  ドライブ文字・UNC パス・`ThisWorkbook.Path` を前提にした文字列連結、`Dir()` での
  存在確認、`Workbooks.Open`、`SaveAs`、外部ブックへのリンクは、そのままでは失敗します。
- **端末に依存する固定値が通りません。** 固定のドライブ文字、ユーザーフォルダ、
  デスクトップ、AppData、Program Files、プリンタ名、IP アドレス、接続文字列などです。
- **古い部品が使えないことがあります。** DAO、DDE、Internet Explorer の自動操作、
  旧式のコントロール、`SendKeys`、`AppActivate`、`VarPtr` / `ObjPtr` / `StrPtr`、
  ハンドルを `Long` で受けている 32 ビット前提のコードなどです。

見つけかたと報告のしかた:

1. まず、上の 5 つの観点でコード全体を読み、当てはまる箇所をすべて挙げてください。
   1 つの API や 1 つのモジュールに限定しないでください。
2. 挙げた箇所ごとに「モジュール名」「該当する処理の名前」「なぜ動かなくなるか」
   「どう直すか（方針）」を書いてください。行番号は不要です。
3. 直しかたは方針だけでよく、コードは書かないでください。
   例:「待ち時間の処理を、標準機能だけで作った関数へ置き換える」
   「ブックの場所は `ThisWorkbook.Path` に頼らず、利用者に選ばせる」。
4. 影響の大きい順に並べ、「動かなくなる」「動くが結果が変わる」「今のところ問題ない」の
   3 段階で分けてください。
5. 問題が見つからない観点は「該当なし」と書いてください。黙って省かないでください。
6. 判断できないところは推測で断定せず、「確認が必要」として理由を書いてください。

## 出力指示

回答はチャットの本文に書いてください。ダウンロード用のテキストファイル、添付ファイル、
ダウンロードリンクでは返さないでください。

これは診断の依頼です。**コードは書かないでください。**
修正後のモジュールや、書き換えたコードのコードブロックは返さないでください。

次の形で書いてください。

1. **結論**（3 行以内）。このマクロは新しい端末でそのまま動くか、直しが要るか。
2. **動かなくなる箇所**。観点ごとに、モジュール名・処理の名前・理由・直す方針。
3. **動くが結果が変わる可能性がある箇所**。同じ形式で。
4. **今のところ問題ない観点**。「該当なし」と 1 行で。
5. **確認が必要なこと**。コードだけでは判断できず、人に聞く必要があることを挙げる。

マクロを書かない人が読む前提で、専門用語には短い説明を添えてください。
直しが必要だと分かったら、この診断結果を持って改めて改修を依頼できます。
