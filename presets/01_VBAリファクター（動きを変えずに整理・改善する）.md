## 説明

今の動きを変えないまま、コードを読みやすく直してもらいます。

## 改修指示

添付したコードを、外から見える動きを変えないまま、読みやすく壊れにくく、
必要なところだけ速く直してください。

進め方は次の順番です。

1. まず読む。どのプロシージャがどこから呼ばれ、どのシート・範囲・外部ファイルを
   読み書きし、何を出力しているかを把握する。
2. 次に選ぶ。下の基準に照らして、このコードとこのデータ量で本当に効く改善だけを
   候補にする。当てはまらない基準は使わない。
3. 最後に直す。選んだ範囲だけを、外から見える動きを保ったまま最小限に変更する。

### 採用がかなり濃いもの

1. セルを 1 つずつ読み書きするループがあり、対象が数百行以上あるなら、対象範囲を
   二次元の Variant 配列へ一括で取り込み、メモリ上で処理し、結果を一括で書き戻す。
   VBA とワークシートの往復回数を減らすことを優先する。
2. 値だけを移している転記は、同じ大きさの範囲どうしなら
   `dst.Value2 = src.Value2` のような直接代入を検討する。
   ただし Copy / Paste は書式・コメント・列幅・数式そのものも移すため等価ではない。
   何を移すつもりのコードかを読んでから決め、機械的に置き換えない。
3. `Select` / `Activate` / `Selection` は、最後に利用者へ画面を見せるなどの
   はっきりした目的がある場合を除いて取り除き、Workbook・Worksheet・Range を
   明示して直接操作する。`ActiveWorkbook` / `ActiveSheet` への暗黙の依存もなくす。
4. `Option Explicit` は維持する。型、`Public` / `Private`、`ByVal` / `ByRef`、
   変数のスコープを明示する。ただし二次元配列など Variant が自然な場所まで
   無理に型を付けない。
5. `ReDim Preserve` をループのたびに実行しない。必要数が先に分かるなら事前に確保し、
   分からないなら一定単位でまとめて広げ、最後に一度だけ実際の件数へ縮める。
   ただし、小規模で十分速いコードをこのために複雑にしない。
6. `Dictionary` は、キーでの検索・照合・重複排除・集計に使う。
   先頭から順に処理するだけの箇所は配列のままにし、何でも `Dictionary` にしない。

### 条件付きで使うもの

7. `ScreenUpdating` / `Calculation` / `EnableEvents` などの停止は、
   シートを大量に更新する範囲・再計算が重い範囲に限って行う。
   変更前の値を保存し、正常終了でもエラー終了でも必ず元へ戻す。
   いわゆる「高速化五点セット」を、全部のマクロへ無条件に足さない。
8. 生の値を読み書きしている箇所は `Value2` を候補にする。
   ただし `Value` の通貨・日付への変換や、`Text` の表示文字列を意図している箇所は
   挙動が変わるため、一律には置き換えない。
9. `Dictionary` の早期バインドと遅延バインドは、配布先を見て選ぶ。
   既存の参照設定を勝手に増やしたり減らしたりしない。
   参照切れを避けたい配布用マクロでは、遅延バインドのままが正しいこともある。

### 保守性と安全性

10. 長い処理は、名前を見れば役割が分かる小さな `Sub` / `Function` へ分ける。
    「何をしているか」を説明する長いコメントは手続きの名前に置き換え、
    「なぜそうしているか」のコメントは残す。短い処理まで細切れにしない。
11. 観測できる動作は変えない。`Public Sub` の名前、イベントプロシージャ名、
    呼び出し順、対象シート、出力する値・数式・書式、メッセージ、外部ファイルの
    読み書きは、そのまま保つ。重複の整理や分割はしてよいが、既存の入口と副作用は守る。
12. `On Error Resume Next` を広い範囲へ掛けない。必要なら失敗し得る 1 文だけに
    範囲を絞り、直後に `Err` を確認して通常のエラー処理へ戻す。
    変更した Application の状態や、開いたオブジェクトの解放は、
    単一の終了経路で確実に元へ戻す。

### やらないこと

- ループをなくすこと自体を目的にする。
- Copy / Paste、`Value`、`Dictionary`、Application の設定を、
  意味を確かめずに一括置換する。
- 短い処理まで過剰に細かく分ける。
- 測っていない箇所を、推測だけで複雑にする。
- 新しい参照設定・外部依存・クラス階層を勝手に増やす。
- 動いている公開入口や出力を「きれいさ」のために変える。

### モジュールの扱い

- 標準モジュール・クラスモジュール・シートやブックのモジュールのどれでも、
  直す必要があるところは直してよい。既存のクラスモジュールも対象に含む。
- 新しく増やすモジュールは標準モジュールだけにする。
  共通化した処理は、新しい標準モジュールへまとめる。

どの基準をどこへ適用したか、そしてなぜ適用しなかった基準があるかは、
出力指示にある SUMMARY の中へ短くまとめてください。

## 出力指示

回答はチャットの本文に書いてください。ダウンロード用のテキストファイル、添付ファイル、
ダウンロードリンクでは返さないでください。

変更したモジュールと新しく作ったモジュールの全文を、**ひとつだけのコードブロック**に
まとめて返してください。モジュールごとにコードブロックを分けないでください。

コードブロックの中は、次の順に書きます。区切りの行は 1 行に 1 つだけ、
そのままの形で書いてください。

まず、何をどう直したかの要約を、この 2 行ではさんで書きます。

'@MACROSTUDIO {{REQUEST_ID}} SUMMARY BEGIN
（何をどう直したか。モジュール名を挙げて 3〜6 行程度。
　マクロを書かない人にも分かる言葉で）
'@MACROSTUDIO {{REQUEST_ID}} SUMMARY END

続けて、モジュールごとに次の行ではさみます。

'@MACROSTUDIO {{REQUEST_ID}} BEGIN <種類> <モジュール名>
（そのモジュールの全文）
'@MACROSTUDIO {{REQUEST_ID}} END <種類> <モジュール名>

すべてのモジュールを書き終えたら、最後に次の 1 行を置いてください。

'@MACROSTUDIO {{REQUEST_ID}} COMPLETE <モジュールの数>

直すところが無いと判断したとき、または、この形では直せないと判断したときは、
モジュールを 1 つも書かず、代わりに次の形で返してください。
求められていない変更を作って埋めることはしないでください。

'@MACROSTUDIO {{REQUEST_ID}} SUMMARY BEGIN
（なぜそう判断したか。何を見て、どこがそうなっているか。
　マクロを書かない人にも分かる言葉で 3〜6 行程度）
'@MACROSTUDIO {{REQUEST_ID}} SUMMARY END
'@MACROSTUDIO {{REQUEST_ID}} NOCHANGE <判断>
'@MACROSTUDIO {{REQUEST_ID}} COMPLETE 0

<判断> は次のどちらかです。

- UNNECESSARY … いまのままで依頼の内容を満たしているので、直す必要がない
- IMPOSSIBLE … 直したほうがよいが、渡されたモジュールを書き換える形ではできない

この 4 行はすべて必要です。理由を書かずに NOCHANGE だけを返したり、
COMPLETE 0 だけを返したりしないでください。何も返さないこと、
返答を途中でやめることも、「変更なし」とは扱われません。

守ってください:

- <種類> は standard / class / form / document のどれかです。
  既存モジュールの <種類> は、依頼文の【対象モジュール】に書かれた種別を
  次のとおり読み替えて書いてください。
  標準モジュール = standard / クラスモジュール = class /
  フォームモジュール = form / ドキュメントモジュール = document
- 新しく増やすモジュールは、必ず standard（標準モジュール）にしてください。
  クラスモジュール・ユーザーフォームを新しく作らないでください。
  既存のクラスモジュールを直すことはできます。
- {{REQUEST_ID}} は今回の依頼の番号です。書き換えたり省略したりしないでください。
- 変更していないモジュールは入れないでください。
- 変更は最小限にする。それ以外の行は、行の順序・空白・インデント・コメント・
  変数宣言の並び・命名を含め、渡したものと一字一句同じにして返す。
- 変更した既存モジュールと、新しく作ったモジュールは、先頭から末尾まで
  省略せず全文を書く。「'（以下変更なし）」のような省略はしない。
- コードブロックの中には、上の区切り行以外の説明文を入れない。
- モジュール先頭に「Attribute VB_」で始まる行を付けない。
- モジュール名の変更と、モジュールの削除はしない。
- 要約は上の SUMMARY の中だけに書きます。コードブロックの外には書かないでください。

## 出力指示（モジュール単位）

回答はチャットの本文に書いてください。ダウンロード用のテキストファイル、添付ファイル、
ダウンロードリンクでは返さないでください。

コードが長いので、変更するモジュールを **1 回の返答につき 1 つだけ** 出してください。
すべてのモジュールを 1 回の返答にまとめないでください。

進め方:

1. まず、変更するモジュールが全部でいくつになるかを決めます。この数を <合計> とします。
2. 1 回目の返答では、要約と 1 つ目のモジュール（番号 00）だけを出します。
3. 返答の最後に、コードブロックの外で「次のモジュール 01 を出してよいですか」と
   1 行で確認してください。
4. 「はい」と言われたら、次の返答で番号 01 のモジュールを出します。
   以後 02、03 … と、<合計> に達するまで 1 回に 1 つずつ繰り返します。

1 回目の返答だけ、コードブロックのはじめに要約を書きます。

'@MACROSTUDIO {{REQUEST_ID}} SUMMARY BEGIN
（何をどう直したか。モジュール名を挙げて 3〜6 行程度。
　マクロを書かない人にも分かる言葉で）
'@MACROSTUDIO {{REQUEST_ID}} SUMMARY END

そして毎回、1 つのモジュールを次の 4 行ではさんで、ひとつだけのコードブロックに
入れてください。区切りの行は 1 行に 1 つだけ、そのままの形で書いてください。
<番号> は 00 から始まる 2 桁、<合計> は変更するモジュールの総数（2 桁）です。

'@MACROSTUDIO {{REQUEST_ID}} PART <番号> OF <合計>
'@MACROSTUDIO {{REQUEST_ID}} BEGIN <種類> <モジュール名>
（そのモジュールの全文）
'@MACROSTUDIO {{REQUEST_ID}} END <種類> <モジュール名>
'@MACROSTUDIO {{REQUEST_ID}} COMPLETE 1

直すところが無いと判断したとき、または、この形では直せないと判断したときは、
モジュールを 1 つも出さず、1 回の返答だけで次の形で返してください。
PART の行は付けません。番号を待つ必要も、続きを出す必要もありません。

'@MACROSTUDIO {{REQUEST_ID}} SUMMARY BEGIN
（なぜそう判断したか。何を見て、どこがそうなっているか。
　マクロを書かない人にも分かる言葉で 3〜6 行程度）
'@MACROSTUDIO {{REQUEST_ID}} SUMMARY END
'@MACROSTUDIO {{REQUEST_ID}} NOCHANGE <判断>

COMPLETE 0 だけを返したりしないでください。何も返さないこと、
返答を途中でやめることも、「変更なし」とは扱われません。

守ってください:

- 1 回の返答に入れるモジュールは 1 つだけです。COMPLETE の数は毎回 1 です。
- <合計> は最初に決めた数のまま、毎回同じ数を書いてください。
- <番号> は 00、01、02 … と 1 つずつ増やします。飛ばしたり戻したりしないでください。
- <種類> は standard / class / form / document のどれかです。
  既存モジュールの <種類> は、依頼文の【対象モジュール】に書かれた種別を
