## PROD-03 — 固定パス置換が「日付書式・数値書式の文字列」をパス候補として提示する（誤検出）

- **重大度**: 高（唯一の「決定的」エンジンが、パスでないものをパスと名乗る）
- **画面**: 4 `repairInput`（ひな形「固定パスを新環境へ置き換える」）
- **試料**: `input_win32_sleep.xlsm`（**実在するパスは 1 つも無い**ブック）
- **再現手順**（すべて実操作）
  1. `input_win32_sleep.xlsm` を読み込む
  2. 画面1で「診断を飛ばして、直したいことを自分で書く」を ON →［次へ］
  3. 画面3で「固定パスを新環境へ置き換える」を選択 →［次へ］
- **期待**: パスが 1 つも無いので候補は 0 件、または「置き換えられる場所は見つかりませんでした」
- **実際**: **「置換の候補 4種類・6か所」** と表示し、次を候補として並べる。

  | 提示された値 | 画面が付けた呼び方 | 実際の正体 | 場所 |
  |---|---|---|---|
  | `/` | 連結された場所の一部 | — | AppController、SystemInfo（2か所） |
  | `0.00` | **ファイル名** | `Format$(…, "0.00")` の**数値書式** | AppController 105行 |
  | `yyyy/mm/dd hh:mm:ss` | 連結された場所の一部 | `Format` / `NumberFormatLocal` の**日付書式** | WindowUtils 431行・509行 |
  | `yyyy/mm/dd` | 連結された場所の一部 | `NumberFormatLocal` の**日付書式** | WindowUtils 499行 |

- **証拠**: `shots\REC_028_S4_repairInput_post.png`
  実コード側の裏取り: `ai-sessions\C1_attachment_source-code-for-ai.md` の
  105行 `Format$(ElapsedSeconds(startedAt, Now), "0.00")` /
  431行・509行 `"yyyy/mm/dd hh:mm:ss"` / 499行 `NumberFormatLocal = "yyyy/mm/dd"`
- **原因**: `presets\02_改修\02_固定パスを新環境へ置き換える.md` の `## 置換の候補` 末尾2行が
  取りこぼし防止の**総なめ規則**になっている。
  ```
  - 連結された場所の一部 | [\\/]              ← スラッシュを1つでも含めば一致
  - ファイル名           | \.[A-Za-z0-9]{1,8}$ ← 末尾が「.英数1〜8」なら一致
  ```
  `yyyy/mm/dd` は前者に、`0.00` は後者に一致する。
  規則は上から順に当てはめ最初の一致で呼び方が決まるため、書式文字列が「場所」を名乗る。
- **影響**: 利用者が候補にチェックして値を入れると、**日付書式・数値書式が一括置換される**。
  日付列の表示形式とログの経過秒表示が壊れる。
- **緩和されている点（公平に記録）**: 全候補は**未チェックで始まる**（実画面で確認済み）。
  置換には利用者の明示的なチェックと値入力が要る。よって黙って壊れることはない。
- **README との関係**: README は固定パス置換について
  「コメント、識別子、数値、日付、文字列の一部分は置き換えません」と約束している。
  日付書式・数値書式の**文字列リテラル**を候補に出す挙動は、この約束の読み手の期待に反する。
- **修正が設計判断を含む点（先生の選択を要する）**:
  末尾2規則を単純に厳しくすると、SharePoint / OneDrive 前提（`BOOK_PATH_IS_URL`）で実在する
  `"/Shared Documents/"` のような**本物のパス断片**を取りこぼす。
  `[\\/]` → `\\` だけの変更では URL 系断片が落ちる。
  ひな形 DSL に除外規則が無いため、「書式文字列を除く」を表現するには
  否定先読みを使うか、DSL に除外欄を足す（＝仕様変更）ことになる。
  **最小修正の候補**: 末尾2規則に否定先読みを付け、書式文字だけで構成された文字列を外す。
  例 `連結された場所の一部 | ^(?![A-Za-z0-9:/\-. ]*$)[\\/]` は `yyyy/mm/dd` を外しつつ
  `\data\` や `/Shared Documents/` を残す。**規則パーサが先読みを通すかの確認が必要。**

## PROD-13 — 長いファイル名で画面0のレイアウトが破綻する【修正済み・実機確認済み】

**重大度: 中（表示のみ。データは壊れない。ただし読み取り結果が読めない）**

### 再現

画面0で `corpus\books\b05\長いファイル名の境界試験…（168文字）.xlsm` を読み込む。

### 実際（`shots\R3_INJ_B05_*` および先生の提示画像）

- コンテンツ列がまるごと右へ押し出され、**画面の左半分が空白**
- カードは右端で切れ、パス表示も枠外
- ［読み取ったコード］［コードの外にあるもの］の**右端の件数**（「3 モジュール・5 行」等）が見えない
- ［次へ］は押せるので、**壊れたまま先へ進める**

### 原因（推測ではなく幾何が一致する）

`assets/css/flow.css` の `.workspace--centered` は `display: grid` + `justify-items: center` だが、
**列トラックに上限がなかった**。暗黙列は `auto` = max-content まで伸びる。

`.task p, .task h2, …` に `overflow-wrap: break-word` は当たっているが、
**`break-word` は max-content 幅を縮めない**。max-content は「一切折り返さずに1行で描いた場合の幅」であり、
168文字の日本語ファイル名では窓幅の数倍になる。

その結果、幅 `--content-flow-w` の `.task` が**巨大なトラックの中央**に置かれ、
左端が窓幅付近まで押し出される。`.workspace { overflow: hidden }` が右を切るため、
「左半分が空白・カードが右へずれて切れる」という見え方になる。観測された左端位置とも一致する。

### 修正

```css
.workspace--centered {
  display: grid;
  align-items: start;
  grid-template-columns: minmax(0, 1fr);   /* ← 追加 */
  justify-items: center;
}
```

トラックを容器幅に固定する。以後、どんな子孫が大きくなっても
**列そのものは動かず**、はみ出しは `.task` の内側で起きて `overflow: hidden` に吸われる。

## PROD-11 — 未修正のまま。理由を書く

置換候補に ProgID（`WScript.Shell`）・コマンド行（`cmd.exe /c echo hello`）・
ワイルドカード（`*.xlsx`）・裸の拡張子（`.csv`）が混じる件。

`lib\verify-path-rules.js` を実行して現状を測った: **出荷中の規則は 40/40 PASS**。
つまり既存の must-keep / must-reject には PROD-11 の形が**1つも入っていない**。
まずコーパスに次を足さないと、直したかどうかを機械で判定できない。

- must-REJECT: `WScript.Shell` `Scripting.FileSystemObject` `cmd.exe /c echo hello` `*.xlsx` `*.*` `.csv`
- must-KEEP: `Report.Backup` `data.csv` `C:\tools\*.xlsx`

**直さなかった理由**: 検討の結果、`Report.Backup` と `Excel.Application` は
**字面が完全に同型**（Word.Word）であり、リテラル単体を見る正規表現では原理的に分離できない。
現在のひな形の規則は「名前 | 正規表現」しか取れないため、
`CreateObject(...)` の引数かどうかという**文脈**を使えない。

取りうる案は次の3つ。**どれも設計判断を含むので、勝手に選ばずここで止める。**

1. ひな形に **ProgID 名前空間の除外リスト**を持たせる（`WScript` `Scripting` `ADODB` `MSXML2` 等）。
   ひな形は業務知識を置いてよい場所なので筋は通る。副作用として `Word.docx` のような
   実ファイル名を取りこぼす（除外リストに `Word` を入れた場合）
2. 規則の書式を拡張して**文脈条件**（`CreateObject` の引数を除く）を書けるようにする。いちばん正確だが影響が広い
3. 直さない。候補は既定チェックでもなく、利用者が外せる

裸の拡張子（`.csv`）と純粋なワイルドカード（`*.xlsx`）だけは**副作用なしに落とせる**
（ファイル名規則の語幹を「1文字以上・先頭がドットでも `*` でもない」に狭めるだけ）。
1と2を保留するなら、この2つだけ先に直す手もある。
