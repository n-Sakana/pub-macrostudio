## 1. 操作方式（この試験の定義）

**合格に数える操作**
- 実ウィンドウを前面にし、前面であることを検証してから、
- `SendInput` による実マウス（実座標）・実キーボード（Unicode 実キー）
- OS のファイル選択ダイアログへの実入力
- 実クリップボード（AI 回答の取り込み）
- Explorer からの実 OLE ドラッグ&ドロップ

**合格に数えない操作**（使用禁止）
- `ExecuteScript` / DOM 直書き / `state` 直書き
- 内部 host API 直呼び / テスト専用ショートカット
- CDP `Input.dispatch*`（前回 E2E の方式。今回は OS レベルへ格上げ）

**安全弁**: 入力の直前に必ず `GetForegroundWindow()` が対象 HWND（またはその子ダイアログ）であることを検証する。
一致しなければ **1 キーも打たずに例外で停止**し、operator:luca へ報告する。

## 2. 証拠（キャプチャ）の規律

- 各操作の**直前**と**直後**、および開閉・選択・遷移・エラー・トースト・ダイアログ表示中を PNG 実撮影
- 命名: `<CASE>_<STEP:3桁>_<label>_<pre|post>.png`（例 `D01_014_pathmap-apply_post.png`）
- 全キャプチャを**実際に目視**し、次を確認する:
  文字切れ / 重なり / 横溢れ / スクロール不能 / 隠れ / ちらつき /
  誤った有効・無効 / 選択状態の戻り / フォーカス逸脱 / 文言矛盾 / 前画面の状態漏れ
- 「保存しただけ」は検証完了に数えない。目視結果を台帳の結果欄へ書く
- 大量反復時も、**全状態遷移**と**代表的な負荷/異常**ごとに証拠を残す。失敗時は必ず直前直後を撮る

## 3. 盲検 AI 応答の規律

1. AI が要る各診断・改修ごとに、**毎回まっさらな内部サブエージェントを 1 体**起動する
2. 回答役へ渡すのは、**MacroStudio が実際に生成した依頼文**と、**その時点の添付ファイル本文**
   （`source-code.md` / 両方経路では `source-code-for-ai.md`）だけ
3. 回答役に見せないもの: MacroStudio の repo / SPEC / テスト / 正解 / 過去試行 / 親の分析
4. 回答役に**ツールを使わせない**（ファイル・shell・web・Room すべて）。与えた本文だけから
   AI チャットとして生の回答を返させる。**ツール無しを実行時に保証できない場合は代替で誤魔化さず停止・報告**
5. 回答は**一字も修正・整形・補完せず**、実クリップボード操作で取り込む
6. 失敗時に勝手な再質問・修正をしない。再試行は**別の新規サブエージェント**による別試行として原文を保存
7. 添付物は SHA-256 を記録し、依頼文・回答原文を `ai-sessions\` へ保存

## 4. 検査（形式受理では合格にしない）

各試行で次まで照合する。

| # | 検査 | 方法 |
|---|---|---|
| V1 | 取り込みの形式受理 | 画面表示 + 実キャプチャ |
| V2 | 診断内容が依頼意図と一致 | oracle の期待環境キー / 期待棚卸しと突合 |
| V3 | 改修コードが「直るべき箇所」を直している | oracle `mustFix` |
| V4 | 「保持すべき箇所」を壊していない | oracle `mustPreserve`（全モジュール・全ストリーム） |
| V5 | 置換保持（両方経路） | 置換後の値が AI 出力にも残る |
| V6 | 最終 VBA の差分 | 原本 → 最終形 |
| V7 | 生成ブックの再読込 | 製品の読み手 + 独立読み出し |
| V8 | 構成保持 | モジュール数・種別・シート・容器構造 |
| V9 | コンパイル | 生成ブックを Excel で開き VBE コンパイル |
| V10 | 安全に実行可能なマクロの期待結果 | oracle `postRun`（セル値） |
| V11 | `result.md` / `exports\` / `temp\` の内容 | 実ファイル読み |
| V12 | **意味的妥当性** | 一見妥当だが意味的に誤る回答を**不合格として分類**（下記 §4.1） |

### 4.1 意味的誤りの分類
- `SEM-OK` … 依頼意図と一致
- `SEM-SHALLOW` … 形式は通るが直すべき本体を直していない（別名化・コメント化だけ等）
- `SEM-WRONG` … 動作を変えてしまう（保持すべき挙動の破壊）
- `SEM-OVERREACH` … 依頼外を書き換えた
- `SEM-REFUSE-OK` … 不成立回答が妥当
- `SEM-REFUSE-BAD` … 直せるのに不成立を返した

製品の合否と AI 回答の質は**別欄**に記録する。AI が誤っても製品が正しく検査・提示していれば製品は合格、
AI の誤りを製品が見逃して通したら製品の不合格。

## 5. 発見 → 修正 → 再試験ループ（Room #4）

```
1. 発見        … 直前直後キャプチャ・正確な操作列・期待/実際・関連ログを先に保存
2. 分類        … 製品不具合 / 試験ハーネス誤り / サンプル・oracle 誤り を区別して記録
3. 最小修正    … 対象原因だけ。既存 dirty 差分は巻き戻さない。無関係リファクタ禁止
4. 同条件再試験 … 同じ試料・同じ OS レベル実 GUI 操作列を最初から再実行し、修正後キャプチャを対にする
5. 関連回帰    … 関連導線 + 既存回帰テスト（docs/DEVELOPMENT.md のテスト群）を実行
6. 続行        … 大量試験へ戻る
```

- UI・状態遷移が変わったら**操作台帳を更新**し、新しく現れた全コンポーネントも操作・撮影する
- 依頼文・回答契約を直した場合は、**新しい依頼文を新規の盲検サブエージェント**へ渡した
  **新回答**で再試験する。古い回答の使い回しで合格にしない
