# 0. 最初に読む — 前任（私）の失敗と、そこから来る規律

`HANDOFF-2.md` §0 は「止まるな」と書いてあり、私はそれを守りました。**守りすぎて事故を起こしました。**

## 起きたこと

コーパス一括投入の途中、`B05`（168文字のファイル名）で**画面のレイアウトが破綻**しました。
私はそれに気づかず、**壊れた画面のまま30冊以上クリックし続けました**。
さらに実マウス・実キー入力で**先生の作業を長時間妨害**しました。

## なぜ気づかなかったか

`HANDOFF-2.md` の「画像は状態遷移・エラー・崩れの確認に限り、値の照合はテキストで行う」を、
**画像を減らす方向にだけ**適用したためです。
一括投入は `run-manifest.json` をテキスト照合する設計にしたので効率は上がりましたが、
**「画面が壊れていないか」を見る手段を自分で捨てていました**。

テキスト照合が答えるのは「読み取りが正しいか」だけです。**レイアウトが生きているかは別の検査です。**

## 後任が守ること（追加）

1. **一括処理には必ず「画面が想定どおりか」の関門を入れる。**
   全件ではなくてよい。数冊に1回、あるいは失敗が2回続いたら止めて撮って見る。
   本件は `could not open the file dialog` が連続した時点で異常でした。**連続失敗は停止条件です。**
2. **「止まるな」は「見るな」ではない。** 安全境界に当たっていなくても、
   **異常の兆候が出たら止まって確認する**のが正しい。それは §0 違反ではありません。
3. **先生の画面を長時間占有しない。** 実マウス・実キーは先生の PC を奪います。
   長い GUI バッチを流す前に**一言ことわる**。「やめろ」と言われたら**即座に全部止める**（説明は後）。
4. 実行中の GUI バッチは `TaskStop` で止め、
   `Get-CimInstance Win32_Process -Filter "Name='powershell.exe'"` で残骸ゼロを確認すること。
