## 6. ハーネスの使い方（`lib\`）

```powershell
# 操作スクリプトは必ず UTF-8 BOM 付きで書く（PS5.1 が ANSI 解釈して日本語が壊れる）
[System.IO.File]::WriteAllText($path, $script, (New-Object System.Text.UTF8Encoding($true)))
powershell.exe -NoProfile -ExecutionPolicy Bypass -STA -File $path
```

### 座標の扱い
撮影は**ウィンドウ矩形**。PNG を見て**表示画像上の座標**を読み `Tap` に渡す。
`Tap` は毎回 `Sync-Rect` して倍率（幅/2000、幅≤2000なら1.0）を再計算し、
**仮想画面外なら1入力も送らず例外**を投げる。

### 踏んだ罠（同じ所で転ばないように）
1. **最初の1クリックが消費される** — 前面化直後のクリックはアクティブ化に使われ WebView2 に届かない。
   `Open-FileDialog` が「クリック→ダイアログ確認→必要なら再クリック」で吸収する
2. **DPI** — per-monitor DPI aware にしないと座標系が丸ごとずれる（実体 primary 3840x2160 / secondary 2160x3840、150%）
3. **スクリプトの文字化け** — UTF-8 **BOM 必須**。oracle の JSON も同様（BOM無しで書くと PS5.1 側の読込が壊れる）
4. **`Type` は `Get-Content` のエイリアス** — 関数名は `TypeText`
5. **here-string の中で `\"` は使えない** — PowerShell では `` `" `` か、素直に別ファイルへ書く
6. **VBA の1物理行は約1,023文字上限** — 超えると Excel が保存を拒否（製品の欠陥ではない）
7. **ひな形を編集すると画面3で選択が破棄される** — 仕様どおり。編集後は選び直す
8. **カーソル着地は数px ずれる** — 許容 8px・3回リトライにしてある

## 7. 安全境界（必ず守る）

- **commit / push / deploy 禁止**
- 先生の実ファイル、`ファイルツリーマネージャー.xlsm`、`audit-results`、既存起動中の Excel/MacroStudio に触れない
- **未追跡ファイルを触らない。削除・掃除・広域 glob をしない**
- 既存 dirty 差分を上書き・巻き戻ししない
- 入力の直前に `Assert-Foreground`。対象が前面でなければ**1入力も送らず例外停止**
- 自分が起動したプロセス／開いた Explorer 窓だけを閉じる
- Excel COM は `AutomationSecurity` を**インスタンス内だけ**設定。Trust Center / レジストリ / 証明書ストアは変更しない

### 署名検証の阻害条件（「未検証」で閉じないこと）
署名付きブックが現物として存在せず（repo と books を走査して 0 件）、新規作成には**コード署名証明書**が要る。
`New-SelfSignedCertificate` も `SELFCERT.EXE` も**利用者の証明書ストアへ書き込む**ため実施していない。
ダミー署名部品の注入は「部品が引き継がれるか」しか示せず、Excel の反応の答えにならない。
→ 境界内で検証できる経路が見つからない場合は、**試した経路と正確な阻害条件を証跡化**して残すこと。

- 依頼ごとに**新規のまっさらな個体**。個体・文脈・過去回答の再利用は**禁止**
- 渡すのは **MacroStudio が実生成した依頼文** と **その時点の添付本文** の逐語のみ
- repo / SPEC / テスト / 正解 / 過去試行 / こちらの分析 / **検査の狙い** は渡さない
- **ツール無しを実測で保証**（`.claude\agents\blind-ai-responder.md` は `tools: []`。
  親ハーネスの `tool_uses=0` で確認する。#10 で先生が許可済み・残置中）
- 回答は**一字も直さず**実クリップボードで取り込む。**形式違反もそのまま投入する**
- 実施は Room の `@blind-ai-orchestrator` へ `BLIND_REQUEST_ID` 付きで依頼

## 10. 前任からの申し送り（技術的な教訓）

- **「テストが緑」と「実物が直っている」は別物**。PROD-05 でこれを踏んだ。
  `countImported` を判別に使い node テストは通ったが、実GUIでは直っていなかった。
  実装担当の実機再走で発覚した。**修正したら必ず実GUIで見ること**
- **製品の自己検証を根拠にしない**。PROD-06 は製品の読み直し検査を通り抜けた
  （読み手は圧縮ソースを読み、Excel は p-code を読んでいた）。
  **必ず実 Excel で開き、コンパイルし、実行し、閉じて再度開く**
- **推測で断定しない**。PROD-06 の原因を最初 `_VBA_PROJECT` と推定して**外した**。
  CFB をストリーム単位で測って初めて正しい場所（モジュール本体の p-code 前置部）に辿り着いた
- **自分の oracle を疑う**。前任は2回誤った（AIのコメントを実コードと誤認 / `Declare` をパス候補の
  `mustFix` に入れた）。製品の不具合として報告する前に、**検査側の誤りでないかを必ず確かめる**
- **黙って return するコードを疑う**。PROD-04 と PROD-09 はどちらも
  「条件を満たさないと無言で終了する」実装が原因で、画面には何も出なかった
- 未完了は件数でごまかさず、**具体的な阻害条件**とともに残すこと
