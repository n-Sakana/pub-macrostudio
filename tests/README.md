# 検証方法

## 今回の実行結果

JavaScript の回帰テスト **92 件成功**、Chromium の画面テスト **13 シナリオ成功**。
差分の入力復元性は、92 件に含まれる 1 テスト内で、乱数シードを固定して **500 ケース**
確認しています。500 件を 92 件に加算してはいません。

同じ 92 件を入力 ZIP のソースに適用した結果は 58 件成功・34 件失敗でした。
失敗件数は不具合の種類数ではなく、異なる入力の回帰テスト件数です。
ログは `results/` にあります。

Windows / .NET Framework / WPF / WebView2 上の C# コンパイル・実行、Excel での
再オープン・コンパイル・マクロ実行は、今回の Linux 環境では **実施していません**。
Windows 用テストスクリプトも、同梱しただけで実行済みではありません。

## JavaScript の回帰テスト

パッケージのルートで次を実行します。npm パッケージの追加は不要です。
実行確認したバージョンは Node.js 22.16.0 です。

```console
node --test tests/test-js.cjs
```

他のソースツリーを検証する場合は `MACROSTUDIO_ROOT` 環境変数をそのルートへ向けます。
返答形式、分割返答、依頼番号、状態破棄、プリセット、テンプレート、出力名、差分、
HTML / JSON のエスケープを確認します。

## ブラウザーの画面テスト

Python、Playwright と Chromium のある環境で実行します。
確認環境は Python 3.13.5 / Playwright 1.57.0 / Chromium 144.0.7559.96 です。

```console
python tests/test-browser.py
```

必要に応じて `CHROMIUM_EXECUTABLE` を Chromium の実行ファイルへ設定します。
テストはローカルの HTML・CSS・JavaScript をブラウザーへ直接読み込みます。
**WebView2 ホスト、クリップボード、ファイル保存、アセット取得はテスト用の代替処理です。**
アセットは実ファイルの内容を用い、通常の画面コードを変更せず評価しています。
このテストの成功は、Windows の保存処理や Excel の正常動作を意味しません。

通常・簡易・相談の画面遷移、分割返答、依頼変更、変更なし回答、名前検査、複数ドロップ、
二重ビルド防止、ホストエラー後の再試行、読み取り不完全時の制御、760 × 440 の
画面領域での入力・フッター操作、テーマ切り替え、単独 HTML 差分レポートを確認します。

## Windows のコンパイル・ファイル読み書き検証（未実行）

64 ビット Windows PowerShell 5.1、.NET Framework、アプリの同梱 DLL が必要です。
PowerShell 7 ではなく Windows PowerShell を使ってください。
組織の実行制限やセキュリティ設定は回避しないでください。

```powershell
powershell.exe -NoProfile -STA -File .\tests\Test-Windows.ps1
```

アプリの全 C# ソースをランチャーと同じ方法でコンパイルし、`CoreRegression.cs` の
12 グループを実行します。圧縮の境界値、VBA 変更・追加の往復、キャッシュ無効化、
変更外の ZIP エントリー保全、元ブック変更検知、既存成果物保護、同時刻の依頼作成、
名前検査、厳密な文字エンコード、原本不変を確認します。

サンプルを `%TEMP%\MacroStudio-audit-<識別子>` へコピーして試験します。
Excel や VBA は実行しません。成功時は自分で作った一時フォルダを削除し、失敗時は
解析用に残します。残ったフォルダの場所は実行ログに表示されます。
**このスクリプト自体の Windows 動作確認も未実施です。**

## サンプルのキャッシュ比較

Python 標準ライブラリのみを使用し、同梱サンプルのデータを読み取ります。
ブックやソースを変更せず、VBA を実行しません。サンプル専用の診断補助であり、
任意の破損ファイルを判定する汎用 CFB 検証器ではありません。

```console
python tests/inspect-sample-cache.py
```

## Windows / Excel の実機確認チェックリスト

| 確認項目 | 確認内容 |
|---|---|
| 起動 | `launch.vbs`、WebView2 未導入時・初回画面読込失敗時、ログ。 |
| 表示 | Windows の表示倍率 100% / 125% / 150%、小画面、ライト / ダーク、入力欄とフッター、IME 変換・カーソル維持。 |
| 基本フロー | 通常・簡易・相談、依頼の編集後の再発行、別ブックへの切替、戻る・やり直す。 |
| 入力 | 実際のファイル選択・ドラッグ＆ドロップ・複数ファイル・クリップボード・ファイル選択のキャンセル。 |
| 返答 | 正常 / 不正な依頼番号、分割の順不同・重複・不足、修正不要 / 不可能、追加標準モジュール、手動修正。 |
| 保存失敗 | 読取専用フォルダ、空き容量不足、長いフルパス、出力ファイルを他アプリが開いている状態、出力フォルダ移動、再試行時の以前のファイルの保全。 |
| 長い処理 | 大きなブック、処理中の追加ドロップ・連打・通常終了。強制終了や電源断に対する完全な保証はありません。 |
| ブックの種類 | 信頼できる `.xlsm` / `.xlam` / `.xlsb` / `.xls` のコピー、既存クラス・UserForm・シート、空モジュール、異なるコードページ、プロシージャ属性。 |
| Excel | まずマクロを無効にして出力を開き、修復ダイアログの有無、VBE のコンパイル、コードの内容、参照設定、ワークシート・書式を確認。安全性を確認したコピーのみ、信頼できる環境で業務操作と計算結果を確認。 |
| 保護・署名 | 開くためのパスワード、VBA の閲覧保護、署名付きプロジェクト。再署名は別工程です。 |

Excel の実行前に AI の変更内容を確認してください。コンパイルに通ることは、安全性・
業務上の正しさ・計算結果の正しさの保証ではありません。
