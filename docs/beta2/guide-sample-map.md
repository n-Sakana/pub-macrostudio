それぞれが狙う環境差分・期待される検出・直し手・再生成と実行の結果。

- 生成: `tests\make-guide-samples.ps1` → `testdata\guide-samples\`（git 管理外）

プロシージャの中に置いてあります。診断はコードを**読んで**見つけるものだから、
実行して再現する必要がありません。

## 既知の未確認点

1. **S08 の ActiveX コントロールをこの端末で作れない。**
   `OLEObjects.Add` / `Shapes.AddOLEObject` のいずれも
   「オブジェクトを挿入できません」で拒否される。`FM20.DLL` は登録済みで
   ファイルも存在するので、コントロールの不在ではなく端末側の制限。
   **信頼センターの設定を緩めて回避することはしない**（ガイド 3.5
   「制限を一律に緩和する手順は標準手順に含めない」）。
   結果として S08 はコード側（`OLEObjects` を触る箇所）だけを持ち、
   棚卸しの ActiveX 件数は 0 のまま。`test-guide-samples.ps1` はこれを
   `UNBUILT` として明示し、期待を満たしたことにはしない。
   ActiveX を持つブックでの棚卸しは `BookInventoryReader` の単体側で
   別途固定する必要がある（未実施）。

2. **Power Query の「接続」は作っていない。**
   クエリ本体（DataMashup）は作れるが、それを `xl/connections.xml` の
   接続として結線するには、Excel がクエリを**評価**する。評価は外部へ
   出る可能性があり、実際に試すとデータモデル経由で応答が返らなくなった。
   自己完結・無副作用の条件を優先し、接続の結線は行っていない。
   代わりに外部ブックリンクで「ブックの外にある接続先」を表現している。
   よって `connections` 経由の検出は**この 10 本では確認していない**。

3. **第 1 段階の AI 診断が実際にどのキーを挙げるかは、まだ通していない。**
   「期待される環境キー」の列は、ガイドと環境定義から導いた期待であって、
   実測ではない。第 5 段階（E2E）で 10 本を実際に診断へ通し、
   期待と実際を突き合わせる。

4. **S04 の `Sleep` はこの端末では通る。**
   EDR / 実行制御のある端末で止まることが `WIN32API_BLOCKED` の前提だが、
   この端末はその環境ではない。止まる側の挙動は未確認。

## 分布について

ガイド §3 は 5 分類だが、3.1（パス）だけが 3 本ある。ガイドの記述量が
最も多い節であることに加え、ドライブ文字・UNC・URL は**失敗の仕方が違う**
（解決できない / 名前が変わる / そもそもファイルシステムではない）ため、
1 本にまとめると診断の期待が曖昧になる。他の分類は 1〜2 本ずつで、
Win32 API・ビット数、参照設定、外部接続、ActiveX、バーコード、信頼設定を
それぞれ独立に持つ。
