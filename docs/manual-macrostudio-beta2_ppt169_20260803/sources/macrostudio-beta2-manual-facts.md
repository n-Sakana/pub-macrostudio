- **機械的置換を先に行う。** 置換予定の行を含んだコードを AI へ渡すと、返ってきたコードに古い値が残るため
  （`docs\SPEC.md` §7.2、`screens.js:330-335`）。

- 置換が済んだ時の案内: `「<n>種類の文字列を置き換えました。続けて、AIへ依頼する内容を決めます。」`
  （`workflow.js:2621-2622`。単独経路では後半の 1 文が付かない）

## 5. 出力・完了

### 5.1 出力ファイル名の検査

`assets\js\screens.js:249-308`。**赤枠と理由文は必ず一致する**（片方だけは不具合として扱う）。

| 条件 | 表示される理由 |
|---|---|
| 空 | 作成するファイル名を入力してください。 |
| 120 文字超 | ファイル名が長すぎます。120文字までにしてください。 |
| `\ / : * ? " < > \|` を含む | ファイル名だけを入れてください。フォルダの区切りや \ / : * ? " < > \| は使えません。 |
| 制御文字を含む | ファイル名に使えない文字が混ざっています。貼り付けた場合は、もう一度入力し直してください。 |
| **Windows の装置名** | 「`<語幹>`」は Windows が装置の名前として扱うため、この名前ではファイルを作っても開けません。別の名前にしてください。 |
| 拡張子なし | 拡張子 `<ext>` を付けた名前にしてください。 |
| 拡張子が違う | 拡張子は `<ext>` のままにしてください。 |

装置名の集合は `^(?:CON|PRN|AUX|NUL|CLOCK\$|COM[0-9]|LPT[0-9])$`（`screens.js:223`）。
**文書からではなく実測で確定した集合**で、`COM0` `LPT0` `CLOCK$` も `COM1..9` `LPT1..9` と同じ挙動を示した
（測定: `qa\run01-blackbox\lib\probe-reserved-names.ps1`）。
最初のピリオドまでの語幹を見て、末尾の空白とピリオドは無視するため `CON.xlsm` `CON .xlsm` `CON.backup.xlsm` は
拒否され、`backup.CON.xlsm` `CONTRACT` `CON1` `COM` `NULL` は通常のファイルとして受理される。

## 7. 置換の対応表（画面 4）

`workflow.js:2156-2292`、`docs\SPEC.md` §7

- 見出し「置換の候補」。説明「コードの文字列として見つかった候補です。置き換えるものだけチェックして、
  置き換え後の値を入力してください。」
- 件数表示「`<n>`種類・`<m>`か所」。候補なしのとき「置き換え候補になる文字列は見つかりませんでした。」
- 行の操作: ［この候補を置き換える］チェック、「置き換え後の値」入力、場所を指す候補には［選ぶ］、
  ［このコードを見る（`<モジュール名>`）］。
- 何を候補として拾うかは**ひな形が決める**。`path-map.js` は規則を当てはめるだけで、パスが何かを知らない
  （`docs\SPEC.md` §7.2）。
- 規則は 2 つのことを言えるようになった（`docs\SPEC.md` §7.2、`presets\02_改修\02_固定パスを新環境へ置き換える.md`）:
  - **捕獲グループ**（丸かっこ）… 置き換えの単位をリテラルの一部にする。接続文字列の中のフォルダーだけを置換できる。
    同じフォルダーが複数の接続文字列に出ても行は 1 つ。
  - **`拾わない文脈`**（5 つ目の欄）… リテラルの直前のコードに当てる正規表現。`CreateObject(` の中の
    `"WScript.Shell"` を場所と誤認しない。ドライブ始まり・UNC・URL・環境変数には使っていない。
- 置換直前にリテラル全体の一致を再確認し、合わなければ **E-MAP-02** で 1 か所も置き換えない。

### 7.1 撮影用ブックの選定に関わる実測

`presets\02_改修\02_固定パスを新環境へ置き換える.md:49-52`（製品自身の記録）:
