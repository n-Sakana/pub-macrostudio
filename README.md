# MacroStudio

**beta 2.0.0（β2.00、未公開・実画面確認前）**

Excel マクロ（VBA）を、**VBE を開かずに、調べて、直して、別名のブックとして保存する**
Windows 用ツールです。判断材料をチャット AI へ渡し、返答を契約どおりに検査して、
差分を見せ、元ブックを上書きせずに書き戻します。

起動後に用途を選ぶ画面はありません。まずブックを読み、事実中心の診断を受けてから、
何を直すかを選ぶ一本道です。

> MacroStudio は、AI の文章から対象や修正内容を推測しません。
> AI が決めた内容は人が読み、人が対象と希望動作を選びます。
> 例外は「固定パスを新環境へ置き換える」ひな形の決定的エンジンだけで、
> ここでもツールが列挙するのは文字列リテラルの位置と値という事実だけです。

---

## まず試す

1. `launch.vbs` をダブルクリックします。
2. Excel ブックを画面へドロップするか、［ファイルを選ぶ］から開きます。
3. 画面右下の［次へ］が青くなったら進みます。戻るときは［戻る］です。
4. 試用には `sample-book\sample_win32_sleep.xlsm` を使えます。

ライト／ダークは右上のボタンで切り替えられ、次回起動時にも維持されます。

対応する入口は `.xlsm` / `.xlam` / `.xlsb` / `.xls` です。拡張子だけでなく中身を
確認して VBA を読みます。開くときにパスワードを求められる暗号化ブックは読み込めません。
Excel でパスワードを外したコピーを保存してから使ってください。VBE 側の
VBA プロジェクト閲覧パスワードは別物です。

## 一本道の4手順

### 1. ブックを読み込む

添付すると、モジュール数、総行数、読み取り結果が同じ画面に出ます。コードを厳密に
読めなかったモジュールと、容器の管理情報だけが標準と違う場合を分けて表示します。

| 表示 | 意味 | 対応 |
|---|---|---|
| マクロのコードは全モジュール読み取れています | 管理情報や格納場所だけが標準と違い、コード本文は読めています | そのまま進めます |
| 一部をバイナリレベルで読み取れませんでした | 名指しされたモジュールのコードが途中までの可能性があります | 改修前後を確認します |

どちらも事実を隠さず表示します。暗号化など、診断材料を安全に作れない場合だけ先へ進みません。

### 2. 第1 AIに事実を診断してもらう

MacroStudio は次を1組にして診断依頼を作ります。

- ブックから取り出した VBA 全文
- `environment\target-environment.json` に記録した想定動作環境
- 診断専用ひな形 `presets\01_診断\01_動作環境の事実監査.md`
- 任意欄「ほかに気になっていること」

同梱環境は「新しい業務端末」（revision `2026-08-01`）で、EDR / DLP 管理下、
SharePoint / OneDrive 利用など24件の前提を、出典と確度付きで持ちます。
**対象端末で観測した事実ではありません。** `declared` / `inferred` と
`observed` を区別したまま AI へ渡します。

［診断依頼を作る］の後、次の2つをチャット AI へ渡します。

- ［依頼文をコピー］でコピーした本文
- ［ファイルの場所を開く］が開くフォルダの `source-code-for-ai.md`

仕様書やエラーの画面など、参考になる資料が手元にあればいっしょに添付してください。
依頼文にも「添付があればそれも踏まえて診断する」と書いてあります。

返答はコードブロック全体をコピーして MacroStudio へ取り込みます。別の依頼 ID、
途中切れ、件数不一致、存在しないモジュール・行・環境キーなどは受理しません。
長い診断は分割返答も受け取れます。欠番、内容の違う重複、矛盾した統合は状態を変えずに
拒否します。

**取り込めなかったときは、どの検査で断ったのかを画面に残します。** 何が違って
いたのかと、次にどうするかが読めるので、同じ貼り付けを繰り返さずに済みます。
チャットが付けた装飾（``` のフェンス、引用の `>`、箇条書き、`&#39;`、
曲がったアポストロフィ、`<code>`）は、取り込む前に機械的に外します。

### 3. 診断を見て、何をどう直すか決める

診断画面は、まず結論を見せ、その次に根拠を置きます。

1. このマクロが何をするものか、対象環境で何が起きるかの2行
2. **要改修 / 要確認 / 改修不要** の件数
3. その3つに分けて並べた指摘
4. 各指摘を開いた中の該当箇所・根拠・**該当行を強調したコード**

判定は2つの事実だけで決まります。改修ひな形のどれかがその環境制約を
「推奨条件」に挙げているか（＝このツールで直せるか）と、AI が付けた区分が
補助（INFO）かどうかです。前者は次の画面の ★推奨 と同じ規則なので、
「要改修」と ★推奨 が食い違うことはありません。

コードは開いたときだけ描き、既定では該当箇所とその前後だけを見せます。
前へ／次へで該当箇所を渡り歩けます。

指摘が0件でも、診断が確認できた範囲と不足した範囲を
`SCOPE_CLEAR` / `INSUFFICIENT` として明示し、黙って成功扱いにはしません。

次に、直す指摘を選びます。選んだ指摘そのもの（何が・どこで・何を壊すか）が
依頼になるので、指摘ごとに書き直す欄はありません。
「追加の要望」を任意で足せます。「自分で改修内容を書く」を選んだときは、
この欄が「改修してほしい内容」という名前で最初から開いています。
AI が返せる答えは 2 つだけです。改修後のコードか、「改修できません」と理由か。
利用者へ質問を返したり選ばせたりする回答は受け取りません。判断材料が足りない
ときも AI は質問せず、何が決まらないのかを理由として返します。それを読んで、
依頼文を書き直してもう一度渡します。
MacroStudio が答えを自動入力することはありません。

通常の AI 改修では、次のひな形から1つ選びます。

| ひな形 | すること |
|---|---|
| Win32 API を使わない形へ直す | Declare で呼んでいる Win32 API を、標準機能へ置き換える |
| OSや外部プログラムへの依存を減らす | 外部プログラムの起動、スクリプトホスト、WMI、古い部品への依存をやめる |
| 新しい保存先で成り立つファイル操作へ直す | 存在確認・パスの組み立て・カレントフォルダの前提を直す |
| VBAリファクター | 今の動きを変えず、読みやすさ・速さ・壊れにくさを直す |
| 自分で改修内容を書く | 希望する改修を自分の言葉で指定する |

ひな形は複数選べます。診断で「要改修」になった指摘は、必ずどれかのひな形が
受け持ちます。どのひな形も受け持たないものは「要確認」か「改修不要」に出ます。

［改修依頼を作る］の後、`repair-request.md` の本文をコピーし、同じ
`source-code-for-ai.md` を第2 AIへ添付します。固定パス置換と組み合わせた経路では、
このファイルの中身は**置き換え済みのコード**です。返答は依頼 ID と区切りを検査してから取り込みます。
長いコードには「モジュール単位出力」を選べます。1回1モジュールを番号順に集め、
全部そろったときだけ1つの改修として適用します。

#### 固定パスだけは決定的に置き換えられる

「固定パスを新環境へ置き換える」は、ひな形がローカルの決定的エンジンを選ぶ経路です。
第2 AIへ改修を依頼せず、画面上で次を行います。

1. VBA を字句解析し、**文字列リテラルだけ**から候補を集めます。
   何を拾い何と呼ぶかは、ひな形の `## 置換の候補` が持つ規則が決めます。
2. 同じ値を1行へ集約し、その文字列がある行を強調したコードを開けるようにします。
   既定は該当箇所のみで、前へ／次へで渡り歩けます。
3. 全候補を未適用で始めます。相対パス、URL、ワイルドカードなどの制限対象は
   根拠を開き、明示的に含めるまで選べません。
4. 利用者が新しい値を入力し、適用する行だけを選びます。
5. 適用直前に、**候補を見つけたときと同じコード**を再解析し、
   記録した文字列と一致したときだけ一括で置き換えます。
   値を直して置き換え直すときも同じ基準から作り直すので、やり直せます。
6. preview diff を確認して、通常と同じ出力工程へ進みます。

任意文字列を受け取る全置換 API はありません。コメント、識別子、数値、日付、
文字列の一部分は置き換えません。1件でも位置や値が変わっていれば全件を中止し、
一部だけ直った状態を作りません。パスの値はログへ書きません。

### 4. 差分を確認して、別名のブックを作る

AI 改修も固定パス置換も、同じ確認画面へ合流します。

- 変更モジュールごとのインライン diff
- 追加／削除行、行内差分、前後の変更への移動
- 変更箇所だけの表示、折り返し
- 必要なときだけ使う手動修正
- 出力名と作成予定ファイル

ビルド前に元ブックの VBA を読み直し、AIへ渡した時点から変わっていないか照合します。
出力後にも生成ブックを再読し、書き込んだ全モジュール、関係しない全ストリーム、
容器構造を検証します。1つでも不一致なら出力を破棄します。

**元ブックは上書きしません。** 改修済みブックは必ず別ファイルです。
差分 HTML は画面と同じ diff 実装を内蔵した自己完結・閲覧専用ファイルで、
外部通信も編集欄も持ちません。

## 実行フォルダと成果物

成果物は**元ブックの隣ではなく、MacroStudio 自身のフォルダの中**に作ります。元ブックの
あるフォルダには何も書きません。最初の診断依頼を作ると、実行ごとに同じ名前のフォルダが
2つできます。

```text
<MacroStudio のフォルダ>\
    exports\<ブック名>_<yyyyMMdd_HHmmss>\
        source-code.md                 # 読み取ったVBA（原本のまま）
        diagnose-request.md
        diagnosis.md                   # 診断を取り込んだときだけ
        repair-request.md              # AI改修経路だけ
        result.md
        run-manifest.json
        <ブック名>-Modified-<yyyyMMdd><元の拡張子>
        <ブック名>-Diff-Report-<yyyyMMdd>.html
    temp\<ブック名>_<yyyyMMdd_HHmmss>\
        source-code-for-ai.md          # AIへ添付する1ファイル
```

［ファイルの場所を開く］が開くのは `temp\` 側で、そこには AI へ渡す1ファイルしか
置きません。置換のみ／両方の経路では**このファイルだけが置換後**のコードになり、
`exports\` 側の `source-code.md` は原本のまま残ります。

依頼を作り直しても同じ実行フォルダ内で世代交換します。前の正常な成果物を壊さず、
一時ファイルへ書いて閉じてから本来の名前へ置き換えます。

## 安全のための境界

- 元ブックは読取元であり、書き込みません。
- 診断依頼 ID と改修依頼 ID は別です。古い返答や別の返答を混ぜません。
- 返答の意味を推測せず、AI が自分で名乗った機械可読な区切りだけを検査します。
- 状態とディスク成果物はホスト書き込み成功後にまとめて確定します。
- 取り込み直しは追加ではなく置き換えです。前回だけにあった変更を残しません。
- ビルドは固定のクライアント timeout で失敗確定しません。ホストの最終応答を待ちます。
- クリップボードの一時競合は50ms間隔、最大10回（待ち合計450ms）だけ再試行します。
  尽きた場合は失敗を表示し、［もう一度コピー］または Ctrl+V で回復できます。
- ログにはコード本文、診断本文、パスの値を書きません。
- WebView2 は同梱ページ `https://macrostudio.local` だけを信頼し、外部遷移、
  新規ウィンドウ、frame、別 origin からのホスト操作を拒否します。

## 想定動作環境とひな形を保守する

### 想定動作環境

`environment\target-environment.json` が唯一のデータ正本です。JSON schema、キー順、
出典、確度を検証し、不正なら診断依頼の作成を止めます。C#、JavaScript、ひな形へ
同じ環境値を複製しないでください。

- データ: `environment\target-environment.json`
- 出典と来歴: `environment\SOURCES.md`
- 更新時の手順: `environment\README.md`

### ひな形

- `presets\01_診断\` — 有効な診断ひな形を**ちょうど1つ**置きます。
- `presets\02_改修\` — 改修の選択肢を置きます。
- `templates\diagnose-template.txt` — 第1依頼の中立な組み立て枠です。
- `templates\repair-template.txt` — 第2依頼の中立な組み立て枠です。

ひな形の Markdown が、説明、指示、返答形式、希望動作候補、維持すること、
記入欄の名前の正本です。テンプレートや製品コードへ文面を複製しません。
固定パスひな形は `## 置換の候補` で**何を拾い何と呼ぶか**を持ちます。
アプリはその規則を当てはめるだけで、パスが何かを知りません。
規則は「この文脈では拾わない」と「この文脈でだけ拾う」を書けます。
プリンタ名のように、字面ではなく使われ方でしか決まらないものは後者で拾います。
置き換え後の値は画面で人が入れます。

改修ひな形は `## 推奨条件` で、自分が受け持つ環境制約を名乗ります。
診断結果の「要改修」と、ひな形カードの ★推奨 は、どちらもこの1つの宣言から出ます。

詳しい見出し、差し込み変数、fail-fast 条件は [仕様書](docs/SPEC.md) §3・§4・§9を
参照してください。

## 動作要件

| 項目 | 要件 |
|---|---|
| OS | Windows 10 / 11 |
| PowerShell | Windows PowerShell 5.1（OS標準） |
| WebView2 Runtime | 必要。無い場合は起動時に案内 |
| .NET Framework | 4.7.2 以降 |
| Microsoft Excel | ツール自体には不要。生成後の動作確認で使用 |
| ネットワーク | MacroStudio 自体はローカル動作。AIとの通信はブラウザ側 |
| インストール | 不要。フォルダ一式をコピー |

配布先では `launch.vbs` をダブルクリックします。開発時はコンソールが見える
`launch.bat` を使えます。ZIP から入手して起動できない場合は、ZIP のプロパティで
［許可する］を付けてから解凍してください。

## うまくいかないとき

- **起動しない／白い画面** — WebView2 Runtime の案内と
  `%LOCALAPPDATA%\MacroStudio\logs\` を確認します。
- **想定動作環境を読めない** — `environment\target-environment.json` と
  `environment\SOURCES.md` を確認します。内蔵値へ置き換えて続行はしません。
- **診断／改修返答を取り込めない** — 区切り行を含むコードブロック全体を
  コピーし直します。別の依頼 ID の返答は使えません。
- **モジュールの欠番が出る** — 足りない番号をAIから受け取るか、
  ［最初から取り込み直す］で番号00から入れ直します。
- **元ブックが読み込み時から変わった** — Excel側の手修正を失わないため停止しています。
  ブックを読み込み直し、診断依頼から作り直します。
- **置き換える場所を確認できなかった** — 何も置き換えていません。
  ひな形を選び直すと、読み込んだときのコードから候補を作り直せます。
- **クリップボードを使えない** — 少し待って［もう一度コピー］を押すか、
  取り込み欄へ Ctrl+V で貼り付けます。
- **ビルドが長い** — 画面に「処理は続いています」と出ている間は待ちます。
  時間だけで失敗扱いにはしません。
- **ビルドに失敗した** — 出力は破棄され、元ブックは無傷です。画面の案内に従います。
